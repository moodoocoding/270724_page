# UX·UI 8인 수정 검토 회의 개요와 만장일치 수정안

## 기록 성격

- 이 기록은 실제 인간 전문가가 참여한 회의가 아니라, 현재 웹페이지 코드와 사용자 피드백을 근거로 수행한 **AI 기반 8개 전문가 역할 시뮬레이션**이다.
- 검토 기준 시점은 `codex/lesson1-design-flow` 브랜치의 1차시·2차시 화면이다.
- 각 전문가의 발언은 100개씩, 총 800개를 요약하거나 합치지 않고 별도 원문 회의록에 기록한다.
- 이 문서는 800개 발언을 대체하는 요약문이 아니라, 모든 발언을 거친 뒤 채택할 **최종 수정 명세**다.

## 만장일치 원칙

### 1. 한 화면에서는 하나의 판단만 요구한다

- 1차시는 교육적 사고 순서를 보존한 A·B·C·D 네 단계로, 2차시는 세 단계로 둔다.
- 한 단계 안에서 필수 입력은 최대 3개를 원칙으로 한다.
- 추가 분석, 자기 점검, 세부 조건은 기본 화면에서 감추고 `선택` 영역으로 둔다.
- 필수 입력과 선택 입력을 색이 아니라 텍스트로 명시한다.

### 2. 질문보다 행동을 먼저 보여 준다

- 단계 제목은 명사형 대신 `배움 정하기`, `장면 적기`, `방법 고르기`처럼 행동형으로 쓴다.
- 각 단계 시작 부분에 `이 단계에서 적을 것 2개`처럼 입력 개수를 표시한다.
- 설명 문단을 먼저 읽게 하지 않는다.
- 입력 라벨만 읽어도 무엇을 적을지 알 수 있게 한다.
- 예시는 입력칸 가까이에 한 문장만 둔다.

### 3. 앞에서 쓴 내용은 다시 쓰지 않는다

- 1차시 A·B·C는 문제 문장에 자동 연결한다.
- 1차시 결과는 2차시 AI 요청에 자동 연결한다.
- 2차시에서 선택한 방법·이유·학생 반응은 최종 설계안에 자동 연결한다.
- 자동 연결된 값은 `1차시에서 불러옴`을 표시한다.
- 원문 수정이 필요하면 해당 차시로 돌아가는 링크를 제공한다.

### 4. 자동 생성 결과와 교사 입력을 구분한다

- 자동 생성 영역은 연한 배경과 `자동 작성됨` 라벨을 사용한다.
- 교사가 직접 작성해야 하는 입력칸은 흰색 바탕과 진한 테두리를 사용한다.
- 자동 생성 결과 아래에 `이 문장은 수정할 수 있습니다`를 표시한다.
- 생성 버튼을 다시 누르면 기존 수정 내용이 바뀔 수 있음을 버튼 근처에서 알린다.

### 5. 저장과 제출은 서로 다른 상태다

- 자동 저장은 상단에서 `저장 중`, `저장됨`, `저장 실패`로 표시한다.
- 제출 버튼 근처에는 현재 차시의 제출 여부만 표시한다.
- 빈칸이 있어도 제출할 수 있다는 정책을 버튼 근처에서 짧게 안내한다.
- 저장 실패 시 입력 내용을 유지하고 다시 저장할 방법을 제공한다.

## 1차시 최종 수정안

### A단계 · 남길 배움 정하기

화면에 바로 보이는 필수 입력:

1. 수업 맥락: 학교급·학년, 교과·단원, 돌아볼 수업 장면을 한 줄에 배치한다.
2. 남길 배움: 가장 넓은 입력칸 하나로 둔다.

화면 문구:

- 단계 제목: `수업 뒤 학생에게 무엇이 남아야 하나요?`
- 남길 배움 라벨: `학생이 이해하고 할 수 있어야 할 일`
- 예시: `자료를 근거로 두 방안을 비교하고, 한 가지를 선택해 이유를 설명한다.`

### B단계 · 현재 장면 적기

화면에 바로 보이는 필수 입력:

1. 직접 보거나 들은 핵심 장면 한 칸

선택 영역:

- 학생이 한 말
- 학생이 한 행동
- 결과물
- 가능한 해석
- 아직 모르는 것
- 다음에 확인할 방법
- 사실과 해석 연습

화면 문구:

- 단계 제목: `현재 장면`
- 핵심 장면 라벨: `직접 보거나 들은 학생의 말·행동`

### C단계 · 확인 기준과 문제 문장 정리하기

화면에 바로 보이는 요소:

1. 다음 수업에서 확인할 핵심 말·행동 한 칸
2. A·B·C 자동 연결 결과

선택 영역:

- 확인 기준 하나 더 쓰기

화면 문구:

- 확인 기준 라벨: `확인 기준 1 · 핵심 작성`
- 자동 연결 결과: `자동 작성됨 · 수정 가능`
- 다시 생성 안내: `초안을 다시 만들면 현재 수정한 문장이 바뀝니다.`

### D단계 · AI 활용 결정하기

화면에 바로 보이는 요소:

1. C단계에서 정리한 수업 문제
2. `AI에게 맡길 일 한 가지` 입력

선택 영역:

- AI 활용 방향
- AI 도움 종류
- 교사가 직접 판단할 부분

자동 문장 형식:

> 현재 수업에서는 [B]. 그러나 [A를 할 수 있는지] 아직 확인하지 못했다. 다음 수업에서는 [C가 나타나는지] 확인할 필요가 있다.

## 2차시 최종 수정안

### 단계 1 · AI 요청 만들기

화면에 바로 보이는 요소:

1. `1차시 내용 자동 연결됨` 요약 한 줄
2. 실제 수업 조건 입력 한 칸
3. 자동 완성된 AI 요청문
4. `복사`와 `Gemini에서 실행` 버튼

선택 영역:

- AI 응답 형식 변경
- Gem 만들기 추가 미션
- 1차시 원문 전체 보기

### 단계 2 · 방법 비교하기

필수 입력 구조:

1. AI 답변 전체를 붙여 넣는 원본 보관 칸 하나
2. 붙여 넣은 답변에서 방법 1·2·3의 이름과 핵심 학생 활동을 자동 분류
3. 자동 분류된 세 방법을 교사가 확인하고 필요할 때 직접 수정
4. 세 방법에 공통으로 확인할 `교사 검토 메모` 한 칸

자동 분류 원칙:

- `방법 1·2·3`, `첫 번째·두 번째·세 번째 방법`, 숫자 제목을 우선 인식한다.
- 세 방법을 모두 찾으면 각 카드에 즉시 입력하고 `자동 분류 완료` 상태를 표시한다.
- 일부만 찾으면 찾은 항목만 입력하고 비어 있는 카드를 명확히 알린다.
- 구분에 실패해도 붙여 넣은 원문은 삭제하지 않는다.
- 자동 분류 결과는 교사가 언제든 직접 수정할 수 있다.

조건 반영 구조:

- `새로 확인한 조건이 있나요?`를 선택 영역으로 둔다.
- 조건이 있을 때만 추가 요청문과 수정 결과 입력칸을 연다.
- 수정된 방법 세 개를 다시 각각 옮겨 쓰게 하지 않는다.
- 수정된 AI 답변은 원문 한 칸으로 받고, 최종 선택 단계에서 필요한 부분만 고른다.

### 단계 3 · 하나를 선택해 설계 완성하기

화면에 바로 보이는 필수 입력:

1. 선택한 방법
2. 선택 이유
3. 교사가 수정할 내용
4. 3차시에서 만들 콘텐츠

자동 연결:

- 사용할 방법과 이유
- 학생 활동
- 확인할 학생 반응

선택 수정:

- 적용할 수업 단계
- 자동 연결된 최종 설계안 직접 수정
- 최종 점검 네 항목

## 공통 화면 구조

```text
[차시 제목]                    [자동 저장 상태]
[01 단계] [02 단계] [03 단계]

이 단계에서 적을 것 2개
1. 질문 또는 입력 라벨
[입력칸                              ]
   짧은 예시

2. 질문 또는 입력 라벨
[입력칸                              ]

[선택 · 더 자세히 기록하기 +]

[자동 생성 결과 또는 다음 행동]
                                    [제출하기]
```

## 마이크로카피 규칙

- `작성해 주세요`를 반복하지 않는다.
- 라벨은 18자 안쪽을 원칙으로 한다.
- 설명은 한 문장, 45자 안쪽을 원칙으로 한다.
- 플레이스홀더는 실제 답안 한 문장으로 쓴다.
- `추가`, `고급`, `기타` 대신 `선택 · 더 자세히 기록하기`를 사용한다.
- `AI 응답 검토` 대신 `방법 비교하기`를 사용한다.
- `교사 선택과 수정` 대신 `하나를 선택해 다듬기`를 사용한다.
- 버튼은 `확인`, `완료`처럼 모호하게 쓰지 않고 `요청문 복사`, `선택 내용 불러오기`처럼 결과를 쓴다.

## 접근성·반응형 합의

- 모든 입력은 보이는 라벨과 연결한다.
- 선택 영역의 열림·닫힘 상태를 보조기기에 전달한다.
- 오류는 색상과 문장으로 함께 표시한다.
- 주요 버튼의 최소 높이는 44px로 한다.
- 키보드 포커스 표시를 유지한다.
- 모바일에서는 단계 탭을 가로로 직접 이동할 수 있게 하고 현재 A·B·C·D 위치를 문자와 단계명으로 함께 표시한다.
- 모바일에서는 두 열 입력을 한 열로 바꾼다.
- 고정 요소가 입력칸이나 제출 버튼을 가리지 않게 한다.
- 긴 자동 생성 결과만 내부 스크롤을 허용하고, 일반 입력 폼에는 중첩 스크롤을 만들지 않는다.

## 구현 우선순위

### P0 · 반드시 반영

1. 1차시는 A·B·C·D 네 단계, 2차시는 세 단계로 구성
2. 필수 입력과 선택 입력 분리
3. 2차시 방법 검토 입력 수 축소
4. 1차시→2차시→최종 설계 중복 입력 제거
5. 자동 작성 영역과 교사 입력 영역의 시각적 구분
6. 저장·제출·오류 상태 구분

### P1 · 함께 반영

1. 단계별 입력 개수 표시
2. 행동형 단계 제목과 짧은 라벨
3. 자동 연결 원문으로 돌아가기
4. 모바일 단계 탭의 A·B·C·D 위치 표시
5. 선택 영역의 키보드·스크린리더 지원

### P2 · 후속 검증

1. 교사 5명 이상으로 무설명 사용성 테스트
2. 1차시 10분, 2차시 15분 이내 완료 여부 측정
3. 중도 이탈 단계와 입력 오류 기록
4. 모바일 360px, 태블릿 768px, 노트북 1366px 확인

## 합의 판정 조건

- 모든 전문가가 P0 항목에 이견이 없어야 한다.
- 전문가별 최종 점수가 모두 95점 이상이어야 한다.
- 평균 점수가 95점 이상이어야 한다.
- 이 점수는 현재 배포 화면 점수가 아니라 **수정안이 구현되었을 때의 설계 평가 점수**로 기록한다.
